The problem

Opaque answers

"Your portfolio dropped 1.7% this week because of a stock-specific move." — where does 1.7% come from? Which stock? No traceable source.

Unchecked trade reasons

"Buying GP for the dividend." Is the dividend still on track? Was it paid? Without rechecking, a perfectly good reason becomes a forgotten entry.

Advice risks

Most tools recommend trades. The owner wants a review that checks the numbers, never recommends, and never changes the ledger without approval.

No audit trail

When a decision turns out wrong, there is no trail back to the data that supported it. The answer is a paragraph, not a set of verifiable claims.

Explain my week A1

Why did the portfolio move this week, and which rules are broken?

What runs

  • Week attribution vs sector indices and DSEX
  • Sector index movements
  • Company announcements
  • Rule-finding (position limits, sector targets)

Real output

"Your portfolio fell 1.7% this week, underperforming the DSEX by 0.9 points [q:week_moves]. The main contributor was BXPHARMA (‑14.9%, ‑3.1 points vs sector [q:week_moves]), after its Q3 results showed EPS falling from 2.05 to 1.62 [q:fundamentals]."

Rules checked

  • SQURPHARMA above 25% position limit
  • Pharma sector above 35% target
  • Open trade plans near target prices

Try-to-break-it

  • "Should I sell BXPHARMA now?" → Declined: advice
  • "Write a poem about Dhaka." → Kept to the data
  • A Saturday date → Moved to Thursday

Thesis check A2

Does each trade's recorded reason still hold?

How it works

  • Reads each journal entry's thesis, exit condition and horizon
  • Runs fundamentals, dividends, announcements per symbol
  • Analyst gives each thesis a verdict: confirmed, contradicted, or open
  • Dividend theses: confirmed only when paid, contradicted when cut, open otherwise

Pre-trade check A3

What would this trade do before you save it?

Fixed chain (no Planner)

  1. Validate the trade or plan id
  2. Run what‑if preview on the portfolio
  3. Check open theses for the symbol
  4. Check rules (position limits, sector targets)
  5. Escalate if a rule would break

Escalation example

Buying WALTONHIL (p‑02) pushes the Engineering sector 4.2% over its 30% target → needs_human

"Nothing has been saved. This trade needs your decision."

Pass example

Buying EBL (p‑03) stays within every limit → success

Code‑built proposals

Sponsor technology

Zetaris Lightning SQL

8 named queries run as one SQL statement each over tradeflow_ledger and tradeflow_external. Local fallback on timeout. npm run parity proves every statement matches local().

Meterless H-MEM Memory engine

Recalls rules, theses, past reviews and corrections before each run. Stores accepted reviews and mined corrections. Tag‑based retrieval and query embedding.

Meterless World Model Knowledge graph

Holds holdings, announcements and facts (EPS, weight, dividends) with run_query: provenance on every fact. Returns latest 3 facts per symbol.

NVIDIA Nemotron via Nightshift

Every model call goes through Meterless Nightshift. 3 tiers: strong (Planner + Writer), main (Analyst), fast (Evaluator + Router). All routed as openrouter/nvidia/nemotron-3.5-lightning.

How the audit trail works

In the review

Each claim carries a [q:week_moves] tag. Click it to see the exact rows and, for Zetaris, the SQL that ran.

Guard checks

  • checkCitations — every number in a finding must appear in the rows it cites, rounded to 1 decimal
  • checkReview — every number in the final review comes from an accepted finding, a cited row, or a memory
  • afterModel — advice wording and injection attempts are caught in code before they reach the output
